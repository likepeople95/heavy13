# 무거운 13

받침대에 올린 바위 무게가 13을 넘으면 그 바위를 올린 사람이 벌점을 떠안는 2~7인 심리전 웹게임입니다. 「데블스 플랜: 데드 어게인」 1일차 감옥매치 규칙을 그대로 구현했습니다. 각자 휴대폰이나 PC로 같은 방에 들어와 실시간으로 함께 합니다.

## 배포하기 (처음 한 번, 5분 정도)

### 1. GitHub에 올리기
1. GitHub에서 새 저장소를 만듭니다. 이름 예시: `heavy13`. 비공개도 괜찮습니다.
2. 저장소 화면에서 **Add file → Upload files**를 누르고, 압축을 푼 `heavy13` 폴더 **안의 내용물 전체**를 끌어다 놓은 뒤 Commit 합니다.
   - `api`, `lib`, `public`, `tests` 폴더와 `package.json`, `vercel.json`이 저장소 맨 위에 있어야 합니다.

### 2. Vercel에 연결하기
1. Vercel → **Add New… → Project** → 방금 만든 저장소를 **Import** 합니다.
2. Framework Preset이 **Other**인지 확인하고, 나머지는 그대로 둔 채 **Deploy**를 누릅니다.
3. 배포된 주소로 들어가면 "저장소 연결이 필요해요" 화면이 나옵니다. 정상이고, 다음 단계로 해결됩니다.

### 3. 저장소(Upstash Redis) 연결하기
1. Vercel 프로젝트 → **Storage** 탭 → **Create Database** → **Upstash for Redis**를 고릅니다.
2. **Free** 플랜으로 만들고, 이 프로젝트에 연결(Connect)합니다. 환경은 Production·Preview·Development 모두 선택합니다.
3. **Deployments** 탭 → 최신 배포 오른쪽 메뉴(⋯) → **Redeploy**를 누릅니다. 환경변수는 다시 배포해야 반영됩니다.

이제 사이트에서 **새 방 만들기** → **초대 링크 복사** → 팀원에게 링크를 보내면 됩니다.

> 환경변수는 `KV_REST_API_URL`·`KV_REST_API_TOKEN` 또는 `UPSTASH_REDIS_REST_URL`·`UPSTASH_REDIS_REST_TOKEN` 중 어느 쪽이든 자동으로 인식합니다.

### 이후 수정할 때
GitHub에 올리면(push) Vercel이 자동으로 다시 배포합니다.

## 무료 한도

Upstash 무료 플랜은 월 50만 명령까지입니다. 이 게임은 화면을 맞추려고 1~1.5초마다 서버에 물어보는데, 5명이 15~30분 한 판을 하면 약 1만~1만 5천 명령을 씁니다. 한 달에 30판 이상은 무료로 할 수 있습니다. 탭을 백그라운드로 내리면 5초 간격으로 줄어듭니다.

## 게임 방법

1. 방장이 방을 만들고 링크를 보냅니다. 각자 닉네임을 넣고 들어옵니다(2~7명).
2. 방장이 설정(고르는 시간, 차례 시간, 남은 패 표시)을 정하고 **게임 시작**을 누릅니다. 자리와 첫 선은 무작위입니다.
3. 매 라운드 카드 1장과 칩 1개를 고르고 **이걸로 내기**를 누릅니다.
4. 공개된 순서대로 자기 차례가 오면 **놓기** 또는 **패스**를 고릅니다. 버튼에 "올리면 합 몇, 벌점 몇"이 미리 나옵니다.
5. 14라운드가 끝나면 순위가 나옵니다. 방장은 **한 판 더 하기**로 같은 방에서 다시 할 수 있습니다.

창을 닫거나 시간이 지나도 게임은 멈추지 않습니다. 제한시간 안에 고르지 않으면 남은 패에서 무작위로 내고, 차례를 넘기면 그대로 놓습니다(레인보우는 벌점이 가장 적은 받침대). 같은 기기·브라우저로 다시 들어오면 자기 자리로 돌아옵니다.

### 규칙 요약
- 각자 바위 카드 0~6(7장), 칩 빨강 2·초록 2·파랑 2·레인보우 1. 14라운드, 7라운드마다 새로 받습니다(받침대는 이어짐).
- 놓는 순서: 레인보우 → 숫자 큰 순 → 같으면 선 플레이어부터 시계 방향.
- 패스한 바위는 맨 뒤에 놓고, 먼저 패스한 사람이 가장 늦게 놓습니다. 남은 사람이 혼자면 패스할 수 없습니다.
- 받침대 합이 13 이상(정확히 13 포함)이 되면, 원래 있던 바위 개수만큼 벌점을 받고 그 바위들은 치웁니다. 방금 놓은 바위는 남습니다.
- 마지막으로 벌점을 받은 사람이 다음 선입니다. 벌점이 같으면 더 최근에 받은 사람이 아래 순위입니다.

## 검증

`npm test`로 아래를 확인합니다. Node.js 20 이상이 필요하고, 설치할 패키지는 없습니다.

| 테스트 | 확인하는 것 |
|---|---|
| `tests/engine.test.js` | 규칙 단위 테스트, **방송 판 14라운드 재생**: 라운드별 선·호명 순서·패스·벌점이 방송과 같고, 최종 벌점 6·8·11·11·14·17·21과 순위(11점 동점 처리 포함)가 일치 |
| `tests/api.test.js` | 실제 HTTP 서버에서 가상 4인이 끝까지 대전, 제출 단계에 남의 카드·칩·토큰이 응답에 없는지 확인, 4명 동시 제출 경합에서 누락 없음, 관전자 차단 |
| `tests/redis.test.js` | 실제 `redis-server`를 Upstash REST 형식으로 감싸 CAS(Lua)·동시성·TTL 확인 후 전체 대전 재실행. redis-server가 없으면 건너뜀 |

방송 판 데이터는 자막으로 복원한 공개 자료라 넷플릭스 원본과 직접 대조한 것은 아닙니다. 자세한 내용은 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)를 보세요.

## 내 PC에서 실행

```bash
npm run dev     # http://localhost:3000 (Redis 없이 메모리로 동작, 서버를 끄면 방이 사라짐)
npm test
```

## 구조

```
api/room.js        Vercel 함수 하나. GET = 내 화면 데이터, POST = 행동(create, join, start, submit, place, pass …)
lib/engine.js      규칙 엔진 (순수 함수, 화면·시간과 무관)
lib/room.js        방·로비·타이머 처리, 플레이어별 화면 데이터(비공개 정보 걸러냄)
lib/store.js       Upstash Redis(REST) / 로컬 메모리 저장소, 버전 비교 저장(CAS)
public/            화면 (HTML·CSS·JS, 빌드 과정 없음)
dev-server.js      로컬 개발 서버
tests/             테스트
```

서버리스라 백그라운드 타이머가 없습니다. 대신 상태에 "다음 일이 일어날 시각"을 적어 두고, 누군가 화면을 새로 받아 갈 때 지난 시각의 일을 차례로 처리합니다. 그래서 모두가 잠깐 화면을 꺼도 다시 들어오면 그사이 진행이 한 번에 반영됩니다.
